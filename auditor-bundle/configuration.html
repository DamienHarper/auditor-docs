Configuration Reference

All configuration options available in auditor-bundle

This section covers all configuration options for auditor-bundle.

📁 Configuration File​

All configuration is done in config/packages/dh_auditor.yaml.

🔍 Quick Reference​

dh_auditor:
    enabled: true                           # Enable/disable auditing globally
    timezone: 'UTC'                         # Timezone for audit timestamps
    user_provider: 'dh_auditor.user_provider'
    security_provider: 'dh_auditor.security_provider'
    role_checker: 'dh_auditor.role_checker'
    extra_data_provider: ~                  # Service adding extra data to audit entries (opt-in)

    providers:
        doctrine:
            table_prefix: ''
            table_suffix: '_audit'
            ignored_columns: []
            ignored_columns_resolver: ~     # Service returning the properties to ignore for an object
            root_resolver: ~                # Service returning extra audit roots of an object
            entity_label_resolver: ~        # Service building the label of an entity written in the diffs
            read_scope: ~                   # Service restricting every query the reader creates
            entities: []
            storage_services: ['@doctrine.orm.default_entity_manager']
            auditing_services: ['@doctrine.orm.default_entity_manager']
            storage_mapper: ~
            utf8_convert: false             # Re-enable legacy UTF-8 conversion (opt-in)
            full_snapshot_on_remove: false  # Record every audited field of removed entities (opt-in)
            batch_size: 0                   # Multi-row INSERTs for audit entries (0: one INSERT per entry)
            compression: false              # Compress diffs/extra_data columns (MariaDB only)
            mask_secret: ~                  # Secret of the #[Mask(strategy: MaskStrategy::KeyedHash)] fields (32 bytes min.)
            skip_disabled_entities: false   # No audit table for entities disabled by their configuration
            viewer: false
            retention:
                schedule: ~                 # Cron expression for scheduled pruning (opt-in)
                default_max_age: ~          # Max age for entities without a policy (scheduled pruning only)

🗄️ Doctrine Provider Options​

All options under providers.doctrine:

table_prefix / table_suffix​

OptionTypeDefaultDescription
table_prefixstring''Prefix for audit table names
table_suffixstring'_audit'Suffix for audit table names
dh_auditor:
    providers:
        doctrine:
            table_prefix: 'audit_'
            table_suffix: ''

Example: Entity table users → Audit table audit_users

ignored_columns​

TypeDefaultDescription
array[]Properties to ignore globally across all entities
dh_auditor:
    providers:
        doctrine:
            ignored_columns:
                - createdAt
                - updatedAt
                - password

ignored_columns_resolver​

TypeDefaultDescription
?string~Service ID of a callable returning the properties to ignore for a given entity object

ignored_columns and the entity options apply to every object of an entity class. To decide per object, implement IgnoredColumnsResolverInterface (or any invokable service) and reference the service:

namespace App\Audit;

use App\Entity\Document;
use DH\Auditor\Provider\Doctrine\Auditing\IgnoredColumnsResolverInterface;

final class DocumentIgnoredColumnsResolver implements IgnoredColumnsResolverInterface
{
    public function __invoke(object $entity): array
    {
        return $entity instanceof Document && $entity->isDraft() ? ['content'] : [];
    }
}
dh_auditor:
    providers:
        doctrine:
            ignored_columns_resolver: App\Audit\DocumentIgnoredColumnsResolver

The resolver is called for every audited entity object on each flush, so keep it cheap. It can only ignore more properties: it never audits a property ignored by the configuration or left out of audited_columns.

root_resolver, entity_label_resolver, read_scope​

OptionTypeDefaultDescription
root_resolver?string~Service ID of a callable returning extra audit roots of an entity object
entity_label_resolver?string~Service ID of an EntityLabelResolverInterface: label of an entity in the diffs
read_scope?string~Service ID of a callable (Query, string $entity): void applied to every query of the reader

See Histories.

entities​

TypeDefaultDescription
array[]Entities to audit and options
dh_auditor:
    providers:
        doctrine:
            entities:
                # Simple: all defaults
                App\Entity\User: ~
                
                # With options
                App\Entity\Post:
                    enabled: true
                    ignored_columns:
                        - viewCount
                    roles:
                        view:
                            - ROLE_ADMIN

                # Only audit a few properties (allowlist)
                App\Entity\Order:
                    audited_columns: [status, total, customer]

                # Entries belonging to the history of another entity
                App\Entity\PropertyFeature:
                    roots: [property]

                # With a retention policy
                App\Entity\Payment:
                    retention:
                        max_age: 'P7Y'      # ISO 8601 duration
                        max_entries: ~      # keep the N most recent entries

Entity options:

OptionTypeDefaultDescription
enabledbooltrueEnable/disable auditing for entity
ignored_columnsarray[]Properties to ignore for this entity
audited_columns?array~Allowlist: only these properties are audited (~: all)
roles.viewarray[]Roles required to view audits
retention.max_age?string~Entries older than this ISO 8601 duration are pruned
retention.max_entries?int~Only the N most recent entries are kept
rootsarray[]Audit root paths, merged with #[AuditRoot] (see Histories)

Audited properties. A property is audited when it is not in the global ignored_columns, not in the entity ignored_columns nor marked with #[Ignore], listed in audited_columns (when set) and not returned by the ignored_columns_resolver for that object. Ignoring always wins over the allowlist.

  • With audited_columns, an update that only changes other properties writes no audit entry; inserts and removals are still audited. audited_columns: [] only records inserts and removals.
  • These options apply to fields and to-one associations (the diffs), not to to-many associations (associate / dissociate entries).
  • ignored_columns and audited_columns must be lists of property names (checked when the container is built).

Retention policies are applied by audit:clean (and by scheduled pruning when enabled):

  • max_age replaces the global audit:clean cutoff for this entity; max_entries applies on top of the age rule.
  • Values are validated when the container is built: max_age must be an ISO 8601 duration greater than zero (P30D, P1Y…), max_entries a positive integer, and only these two keys are allowed.
  • They override the #[Auditable(maxAge: ..., maxEntries: ...)] values key by key: setting only max_age keeps the attribute maxEntries, and max_age: ~ explicitly disables the attribute maxAge (e.g. per environment).
  • Without any retention option nor attribute value, nothing changes: the entity follows the global audit:clean cutoff, as before.

storage_mapper​

TypeDefaultDescription
string|nullnullClass name of an invokable class (constructor without arguments) routing audits to storage services; it is not a service ID

Required when using multiple storage services.

dh_auditor:
    providers:
        doctrine:
            storage_mapper: 'App\Audit\StorageMapper'

NOTE

See Multi-Database Setup for details.

utf8_convert​

TypeDefaultDescription
boolfalseRe-enable the legacy UTF-8 conversion pass
dh_auditor:
    providers:
        doctrine:
            utf8_convert: false

In auditor 3.x, every audit entry value was passed through mb_convert_encoding() automatically. In auditor 4.0+ this implicit conversion is disabled by default because DBAL 4 enforces UTF-8 connections on PHP 8.4+, making the conversion a no-op for virtually all modern applications.

If your application reads data from legacy non-UTF-8 sources, you can re-enable the conversion explicitly:

dh_auditor:
    providers:
        doctrine:
            utf8_convert: true

NOTE

Enabling this option has a small performance cost as every stored value is passed through mb_convert_encoding(). Leave it disabled unless you know your data sources may produce non-UTF-8 strings.

full_snapshot_on_remove​

TypeDefaultDescription
boolfalseRecord the last value of every audited field of a removed entity

By default, a remove entry only identifies the deleted entity (getDiffSource()), with empty changes. With this option, it also records every audited field as old, with new set to null: the viewer then shows the last state of the deleted object. Remove entries get larger.

dh_auditor:
    providers:
        doctrine:
            full_snapshot_on_remove: true

batch_size​

TypeDefaultDescription
int (≥ 0)0Write the audit entries of a transaction with multi-row INSERTs

With 0, each audit entry is written with its own INSERT. A positive value buffers the audit entries of the database transaction being committed and writes them with multi-row INSERTs, right before the COMMIT or as soon as batch_size entries are buffered: flushes of many entities are faster. Values between 100 and 1000 are a good start; the LifecycleEvent payload of a buffered entry has no id. See the provider's Batch INSERT documentation for the trade-offs.

dh_auditor:
    providers:
        doctrine:
            batch_size: 500

TIP

The default stays 0 only because a buffered entry has no id in its LifecycleEvent payload. If no listener of your application reads $payload['id'], batch_size: 500 makes flushes of hundreds of entities 10 to 18 % faster on SQLite, 19 to 51 % on MySQL and 44 to 67 % on PostgreSQL (see the provider's Performance page).

compression​

TypeDefaultDescription
boolfalseStore the diffs and extra_data columns compressed (MariaDB only)
dh_auditor:
    providers:
        doctrine:
            compression: true

On MySQL and MariaDB, audit tables can become the largest tables of a database, almost entirely because of the diffs column. On MariaDB, this option declares diffs and extra_data as compressed columns (JSON COMPRESSED): MariaDB compresses and decompresses them transparently, so the viewer, the Reader, JsonFilter and JSON functions in SQL keep working unchanged.

Compression trades CPU for disk space and I/O: reading a large history that is already in memory gets slower (every value is decompressed, about twice as slow for an entity with ~500 changes), while reads hitting the disk and writes get faster since there is much less data to move.

The option has no effect on other platforms:

  • PostgreSQL already compresses large JSONB values automatically (TOAST);
  • MySQL has no column compression. If disk space matters more than speed, InnoDB page compression can be enabled manually on audit tables (ALTER TABLE ... COMPRESSION='zlib' followed by OPTIMIZE TABLE);
  • SQLite has no compression.

New audit tables are created compressed. Existing audit tables must be converted by running:

# Preview, then apply
bin/console audit:schema:update --dump-sql
bin/console audit:schema:update --force

If you manage your schema with Doctrine Migrations, copy the SQL shown by audit:schema:update --dump-sql into a migration: doctrine:migrations:diff does not detect the compression of existing columns (and never reports a difference for compressed columns either). Converting rewrites the audit tables and compresses existing entries, which can take a while on large tables. Before MariaDB 11.2, writes to the audit tables are locked during the rewrite, so audited flushes wait for it; since MariaDB 11.2, the rewrite runs online by default (ALGORITHM=COPY, LOCK=NONE). Setting the option back to false and running audit:schema:update again restores uncompressed columns without losing data.

NOTE

See the DoctrineProvider configuration for details.

mask_secret​

TypeDefaultDescription
string | nullnullSecret of the #[Mask(strategy: MaskStrategy::KeyedHash)] fields, at least 32 bytes

Keys the HMAC-SHA256 stored instead of the value of a field marked with #[Mask(strategy: MaskStrategy::KeyedHash)] (see Attributes). A flush that writes a keyed hash without it throws.

dh_auditor:
    providers:
        doctrine:
            mask_secret: '%env(AUDIT_MASK_SECRET)%'

Changing the secret changes the hashes recorded from then on: the entries recorded before can no longer be matched with the new ones.

skip_disabled_entities​

TypeDefaultDescription
boolfalseNo audit table for entities disabled by their configuration (enabled: false)
dh_auditor:
    providers:
        doctrine:
            skip_disabled_entities: true

An entity disabled by its configuration (#[Auditable(enabled: false)] or enabled: false under entities) is not audited, but it still gets an audit table by default, so that auditing can be enabled for it at runtime with enableAuditFor(). If you never do that (e.g. a linter requires #[Auditable] on every entity and some are never meant to be audited), this option leaves such entities without an audit table:

  • audit:schema:update, doctrine:schema:update and doctrine:migrations:diff all skip them;
  • enableAuditFor() throws a LogicException for them, instead of a flush failing later on a missing table;
  • the viewer and the Reader leave them out.

Existing audit tables of these entities are not dropped. See the DoctrineProvider configuration for details.

viewer​

TypeDefaultDescription
bool|arrayfalseEnable/configure audit viewer
# Simple enable
dh_auditor:
    providers:
        doctrine:
            viewer: true

# With options
dh_auditor:
    providers:
        doctrine:
            viewer:
                enabled: true
                page_size: 50

Viewer options:

OptionTypeDefaultDescription
enabledboolfalseEnable the viewer
page_sizeint50Actions per page of the lists of actions; revisions per page of the revisions of an object; default entries per page of the <twig:DhAuditor:History> component
activity_grapharrayActivity graph of the overview (enabled, days, layout, cache), see Activity Graph

retention​

Scheduled pruning of audit entries with Symfony Scheduler. Disabled by default: nothing is ever deleted automatically unless schedule is set.

OptionTypeDefaultDescription
schedule?string~Cron expression (e.g. '0 3 * * *', '@daily') enabling scheduled pruning
default_max_age?string~ISO 8601 duration applied to entities without a max_age policy
dh_auditor:
    providers:
        doctrine:
            entities:
                App\Entity\Payment:
                    retention:
                        max_age: 'P7Y'
                App\Entity\Session:
                    retention:
                        max_entries: 10000
            retention:
                schedule: '0 3 * * *'   # every day at 3 AM

A scheduled run applies the same rules as audit:clean, with one difference: there is no implicit global retention period. Only explicit policies are applied (entity retention options or #[Auditable] values); an entity without a policy is left untouched, unless default_max_age is set.

Requirements:

composer require symfony/scheduler symfony/messenger dragonmantank/cron-expression

Then run the schedule's worker (e.g. with a process manager):

php bin/console messenger:consume scheduler_dh_auditor_retention

Notes:

  • Every policy is validated before anything is deleted; an invalid one makes the run fail without deleting anything.
  • A scheduled run shares the audit:clean lock: if the command is running on the same host, the run is skipped.
  • The configuration is validated when the container is built (cron expression, durations, allowed keys).

Logging​

No option is needed: the bundle injects the application's logger service into the Doctrine provider. The provider logs, at the error level, the failures it cannot throw without hiding the original error, e.g. audit entries stored on another connection that could not be deleted after their transaction was rolled back (the log context gives the transaction_id and the audit table, to clean them up by hand).

With MonologBundle, these messages go to the dedicated auditor channel, as do the info messages of the scheduled pruning (one per pruned entity, or when a run is skipped), so they can be routed to their own handler:

# config/packages/monolog.yaml
monolog:
    handlers:
        auditor:
            type: stream
            path: '%kernel.logs_dir%/auditor.log'
            level: error
            channels: ['auditor']

Without a logger service, nothing is logged.

📝 Complete Example​

# config/packages/dh_auditor.yaml
dh_auditor:
    enabled: true
    timezone: 'Europe/Paris'
    
    providers:
        doctrine:
            table_suffix: '_audit'
            
            ignored_columns:
                - createdAt
                - updatedAt
            
            entities:
                App\Entity\User:
                    roles:
                        view: [ROLE_ADMIN]
                
                App\Entity\Post:
                    ignored_columns:
                        - viewCount
                
                App\Entity\Comment: ~
            
            viewer:
                enabled: true
                page_size: 100
